# Vetchium API contract

This directory is the source of truth for Vetchium HTTP API paths and wire
types. Every `.tsp` file has a corresponding hand-maintained `.go` file; Go
types are intentionally not generated by a TypeSpec emitter. The sole
exception is `main.tsp`, which is only the TypeSpec compiler entry point and
does not define wire types.

- `common/` contains genuinely shared scalar and value types.
- `problem/` contains the RFC 9457 representation and the API-wide catalog of
  stable problem types. Files may be grouped by API surface while remaining in
  the single `problem` Go package.
- `admin/`, and future surface directories, contain endpoint-specific paths,
  request bodies, success bodies, and complete HTTP response envelopes.
- `main.tsp` is the TypeSpec compiler entry point and therefore has no matching
  Go file.

The Go module is consumed by the backend through the local replacement in
`backend/go.mod`. Add new server code by importing the appropriate package
under `github.com/vetchium/src/typespec`; do not duplicate API body structs in
handlers.

Problem call sites use the package name as context, for example:

```go
httpx.WriteProblem(w, problem.NewInvalidCredentials())
```

To validate the contract and emit OpenAPI 3.1 locally:

```sh
npm ci
npx tsp compile .
```

Emitter output is written under `tsp-output/` and is not committed.
