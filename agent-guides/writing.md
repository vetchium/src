# Writing

Applies to all text: guides, docs, comments, commits, pull requests, UI copy,
and replies to the developer.

## Standard

- Write in a standard like ASD-STE100.
- Use at most 20 words for an instruction and 25 for a description.
- Use the active voice and one instruction in each sentence.
- Give each word one meaning. Use the product terms in
  [`glossary.md`](glossary.md).
- Prefer tables and lists to paragraphs.

## Precision

- Lead with the answer, the result, or the decision. Give the reason after it,
  and only when the reader needs it.
- Name the exact thing: the file and line, the command, the route, the number,
  the error text. Never use "this" or "it" when two nouns can match.
- Say what you verified and how. Say what you did not verify.
- State a real uncertainty once, with what is unknown and how to check it.
- Stop when the content stops. No summary of what you just wrote.

## Banned patterns

| Pattern | Examples |
| --- | --- |
| Correction of a claim nobody made | "It is not X, it is Y", "not just X, but Y", "This isn't about X" |
| Hype and intensifiers | "crucial", "robust", "seamless", "powerful", "truly", "really", "very", "significantly" |
| Filler at the start or end | "Great question", "Certainly", "Let's dive in", "In short", "I hope this helps" |
| Hedges without a stated unknown | "might", "perhaps", "it seems", "arguably", "should work" |
| Figures of speech | "under the hood", "deep dive", "the heart of", "game changer", "at the end of the day" |
| Reveal rhythm | a rhetorical question, "The result:" before a fact, a list of three for cadence |
| Asides | a dash or parenthesis that holds a second sentence; write two sentences |
| Apology or praise | "Sorry for the confusion", "Good catch" |
